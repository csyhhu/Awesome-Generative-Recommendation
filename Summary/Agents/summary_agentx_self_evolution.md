# AgentX: Towards Agent-Driven Self-Iteration of Industrial Recommender Systems

> **论文链接**: https://arxiv.org/abs/2606.26859
> **团队**: AgentX Team (快手/Kuaishou)
> **核心贡献**: 提出并部署了 AgentX——一个面向工业推荐系统的多智能体自迭代开发框架，在快手 App 主 Feed 和生活服务场景取得了显著的在线业务收益。

---

## 1. 动机与问题

工业推荐系统的算法迭代长期依赖算法工程师的持续参与，一个完整迭代周期涉及数据分析、特征工程、模型开发、上线部署、A/B 测试和归因复盘，发布周期通常以周为单位。核心瓶颈在于：

- **迭代产出与人力线性绑定**：创新产出随人员数量线性增长，无法随证据、算力和实验知识积累产生复利效应。
- **工程师精力分散**：大量时间被消耗在数据拉取、配置修改、流水线维护等重复性工作，而非高价值的假设提出和方向判断。
- **现有自动化方案存在三个结构性缺口**：
  1. **缺乏真实在线反馈**：现有系统多依赖离线指标或人工评分，而非真实业务价值对齐的在线 A/B 结果。
  2. **未在工业规模验证**：公共数据集规模远小于真实推荐系统（十亿级样本、多目标耦合、多业务线并行）。
  3. **缺乏持续演进机制**：大多数 ML 工程智能体系统在单次任务完成后不累积参数、提示词和工作流，无法形成长期复利效应。

## 2. AgentX 系统设计

AgentX 将推荐系统迭代从人工驱动的串行流水线重构为智能体驱动的闭环系统，包含四个紧密耦合的阶段：

### 2.1 整体架构

```
用户意图 → Brainstorm Agent → Developing Agent → Evaluation Agent → 在线反馈
              ↑                                                    |
              └────────── Harness Evolution (SGPO) ◄───────────────┘
                              (轨迹数据回流)
```

### 2.2 Brainstorm Agent（头脑风暴智能体）

作为 AgentX 循环的入口点，将模糊的优化意图转化为一组**排序后可执行**的实验提案。核心设计包括：

- **问题界定（Question）**：将不完整的用户意图转化为明确的任务边界，使不确定性显式化。
- **有界提案探索（Bounded Proposal Exploration）**：
  - 批量生成候选方向（非单一自由形式响应）
  - 三种成熟度状态：`Ready-to-implement`（可实施）、`Probe-first`（需先探测）、`Moonshot-backlog`（远期储备）
  - 每轮迭代维护 `avoid set`，避免重复生成相同方向
- **证据加权生成（Evidence-Weighted Generation）**：从四个知识源检索证据：
  - **Experiment KB**：历史实验记录、结论和教训
  - **System KB**：模型架构、特征定义、DSL 行为、代码边界（三层结构化领域维基）
  - **Data Analysis**：基于数据的经验验证（指标诊断、分段行为、分布偏移）
  - **Model Research**：将论文转化为可执行提案知识（结构化事实存储、生产基线约束检查）
- **评分公式**：\(S(c|q) = \lambda_o O + \lambda_b B + \lambda_f F + \lambda_h H + \lambda_e E - \lambda_r R\)
- **验证与交付**：通过人审门控后，生成正式实验记录和开发交付方案。

### 2.3 Developing Agent（开发智能体）

将已批准的提案转化为**可验证的代码产物**，分为两条并行轨道：

#### 在线策略轨道
- **仓库锚定代码生成**：强制在编码前查询 Schema（用户侧/上下文侧/Item 侧特征结构体）、DSL 检查器、C++ 语法检查器等。
- **验证导向实现循环**：抽象实施计划 → 原子子需求实现 → 组装补丁 → 确定性验证 → 针对性修复。
- **八维代码质量评分**（\(Q_{code}\)）：
  - 属性幻觉（22%）、正确性循环迭代（18%）、人工干预（18%）为最高权重维度（合计58%）
  - 三个严重级维度直接威胁自主生产可靠性

#### 离线模型轨道
- **单轮流水线**：`policy → (code ↔ verify) || experts×N → exec → final_review`
- **可证伪归因**：声明的因果链必须在训练日志中逐链验证，未归因的 AUC 增益会被记录为刹车信号，不会传播到知识库。
- **平台故障鲁棒执行**：纯函数分类器区分确定性错误（NaN 梯度、特征表冲突）和瞬时故障（日志停滞、基础设施中止），分类处理。
- **RankMixer 案例**：第1轮乘法门因初始化问题梯度消失 → 第2轮残差修复获 ΔAUC=+0.0022 并全链验证通过。

### 2.4 Evaluation Agent（评估智能体）

将已有代码变更的在线 A/B 结果转化为整个系统可依赖的奖励信号：

- **安全部署与流量分配**：映射业务域/世界、选择分流因子、分配互斥流量桶、预实验平衡检查。
- **参数白名单 + 灰度发布**：API 提交后观察最小灰度窗口，监控不稳定立即中止。
- **A/B 判断与护栏否决**：
  - 护栏按业务域划分（非通用），使用复合经济交换指标（非单指标硬否决），阈值设计为关注信号（非绝对阻塞）。
  - 结构化裁决：KEEP / EXTEND / DISCARD + 主效应 + 护栏状态 + 统计方法 + 观测窗口。
- **负面结果资产化**：将 DISCARD 的实验结果按根因标注（显著性不足、护栏恶化、流量不匹配等），按管道阶段、业务目标、用户分段索引，供后续头脑风暴检索以避免重复失败方向。

### 2.5 Harness Evolution（执行层演进：SGPO）

基于执行轨迹优化智能体自身的提示词/规范，而非推荐策略本身。

#### SGPO-I：基于对话轨迹
- **语义梯度计算**：评估智能体分析轨迹失败原因，输出结构化的自然语言诊断。
- **候选规范生成**：提炼智能体将梯度转化为局部 harness 编辑（仅限指令、验证规则、输出契约、工具使用规范）。
- **成对重放准入**：在相同任务上比较新旧 harness，仅当 ΔJ > ε 且安全检查通过时才接受更新。
- **Brainstorm Agent 演进案例**：5 轮后标准化重放得分从 75.15% 提升至 98.00%。

#### SGPO-II：基于代码 MR 历史
- 证据源从对话轨迹切换为历史合并请求（MR），滤除噪声变更（批量格式化、revert、少于10行、超过5000行等）。
- 五维评估标准：语义正确性（40%，硬门限≥4）、需求覆盖（25%）、文件覆盖（20%）、默认安全（10%）、代码风格一致性（5%）。
- **Case Study**：复杂异步模块得分从 2.60 提升至 4.90（+88%）。

#### 模型研究探索流水线演进
- **三阶段搜索**：Phase 1 论文复现筛选 Top-K → Phase 2 模块消融确认有效模块 → Phase 3 跨论文模块组合。
- **记忆引导剪枝**：论文级剪枝（核心前提被证伪则排除所有模块）+ 模块级剪枝（消融无效）+ 饱和度检测（新颖性签名重复率 >80% 终止）。
- **经验飞轮**：阈值门控（至少两次独立运行）+ 对抗性评审门控（专门智能体尝试证伪因果机制）。

### 2.6 全链路示例：提升低活用户 Feed 时长

> **注意**：论文中未给出单个 idea 贯穿全链路的完整示例，以下根据论文各模块描述构造一个具象化的 walkthrough，每个步骤严格对应论文中描述的实际机制。

---

**用户意图输入**：*"最近低活用户的 Feed 时长在下降，帮我看看能不能通过调整排序策略来改善。"*

#### 阶段 1 — Brainstorm Agent

| 步骤 | 行为 |
|------|------|
| **问题界定** | 将模糊意图转化为明确任务：*"如何在不损害高活用户体验的前提下，提升日活<3次用户的 Feed 观看时长？约束：仅允许改动精排队列打分逻辑。"* |
| **四源证据检索** | ① Experiment KB → 检索到历史实验 "低活加权+5% → 正向但噪声大，被护栏否决"；② System KB → 查到 `user_active_level`、`user_recent_watch_cat` 可用字段；③ Data Analysis → 低活用户内容消费集中度比高活用户高 2.3×；④ Model Research → 检索到 dwell-time aware re-weighting 论文 |
| **批量提案** | P1: 低活用户侧直接 CPM Boost（`Probe-first`，历史噪声）；P2: 基于 content-category affinity 的动态权重修正（`Ready-to-implement`，得分最高）；P3: cross-domain transfer embedding（`Moonshot-backlog`） |
| **avoid set** | 记录 P1 方向hash，避免下轮重复 |
| **人审门控** | P2 通过，生成正式实验记录和开发交付方案 |

#### 阶段 2 — Developing Agent（在线策略轨道）

| 步骤 | 行为 |
|------|------|
| **Schema 锚定** | 查询 `UserFeatureSchema`（确认 `user_active_level` int32）和 item 侧 `item_category_id`（int64）可用 |
| **原子子需求分解** | ① 计算用户-类目 affinity 向量 `affinity[cat_id]`；② 在精排打分中插入动态权重 `final_score *= 1.0 + λ × affinity[item_category_id]`（仅低活用户触发）；③ 添加 feature flag `enable_low_active_affinity_boost`（默认关闭） |
| **验证循环** | 第1轮：affinity 未做平滑 → 类目权重爆炸 → 加 Laplace 平滑修复；第2轮：DSL 检查器报类型不匹配 → 修复；第3轮：通过 ✓ |
| **八维质量评分** | 无属性幻觉、正确性通过、人工干预量低 → 通过 |

#### 阶段 3 — Evaluation Agent

| 步骤 | 行为 |
|------|------|
| **安全部署** | 业务域=主 Feed，分流因子 `user_id % 100`，实验组/对照组各 5% 流量，预平衡检查通过 |
| **灰度发布** | 0.1% 最小灰度窗口 30 分钟 → 无异常 → 放量至 5% |
| **A/B 判定**（7天后） | 低活用户时长 **+0.41%**（p<0.001）、高活用户时长 -0.01%（不显著）、护栏次日留存 +0.05%（p=0.31，未恶化） |
| **裁决** | **KEEP** ✅ → 结果入职 Experiment KB（标注因果机制：`low-active + category-affinity + dynamic-weight`） |

#### 阶段 4 — Harness Evolution（SGPO-I）

> 假设此任务暴露出 Brainstorm Agent 的一个系统性问题：早期提案未包含 "business-causal chain"，下游 Developing Agent 误解意图。

| 步骤 | 行为 |
|------|------|
| **轨迹采样** | 抽取该任务的多轮 Brainstorm 对话 |
| **语义梯度** | Evaluator 诊断：*"提案缺少因果链 → Developing Agent 无法区分 '低活用户本身就喜欢长视频' vs '低活用户需要被推荐更多长视频' → 权重方向实现错误"* |
| **harness 编辑** | Refine Agent 在 Brainstorm 输出契约中新增：*"每个提案必须包含 business-causal chain：因为[用户行为证据] → 所以[策略机制] → 预期[效果路径]"* |
| **成对重放** | 旧 harness 重放 3.7/5.0 → 新 harness 重放 4.5/5.0 → ΔJ=+0.8 > ε(0.3) → **接受更新** ✅ |

此后所有 Brainstorm 提案自动携带因果链，下游不再误判。

## 3. 实验结果

### 3.1 生产环境部署（快手 App，三周）

| 指标 | AgentX Worker | 人工工程师 | 倍数 |
|------|:---:|:---:|:---:|
| 并发实验数（每周） | 12 | 1.5 | **8×** |
| Launchable Results/周 | 1.1 | 0.08 | **13.8×** |
| 累计 App 时长增益/周 | 0.0623% | 0.0167% | **3.7×** |
| 单 idea 上线转化率 | 2.7% | 5.1% | 0.53× |

- **主 Feed**：374 个 idea → 106 个通过审查 → 100 个上线 → 10 个可上线结果 → 累计 **0.561%** App 时长增益
- **生活服务**：超 **1 亿人民币**年化营收
- **自我进化效应**：三周内周并发实验量翻4倍（15→60），idea 通过率翻3倍（15%→45%），周可上线结果翻倍（2→5）
- **瓶颈分析**：91.4% 的 idea 拒绝来自平台和基础设施约束（参数资源冲突 64.7%），仅 8.7% 为智能体自身错误

### 3.2 模型研究实验（独立研究）

- 复现 113 篇论文，Top-10 种子论文
- 自动分发 214 个跨论文架构组合实验
- 84.1% 完成率，57.8% 超越基线
- 22 个进入线上 A/B，5 个正向，2 个最终上线
- 模型侧 LR 带来 **0.865%** 直播时长增益

### 3.3 PCV 增强约束精排案例（两轮闭环迭代）

- **Loop 1**：直接 PCV 增强 → 正向但噪声大（用户时长 +0.021%，活跃设备 -0.023%）
- **Loop 2**：约束 PCV 排序（质量门控 + 活跃度感知动态权重 + 时长导向基分）→ 用户时长 +0.071%，真实展示 +0.118%

### 3.4 专家智能体协同案例（生活服务）

- 推荐决策智能体提供用户级诊断 → AgentX 将诊断转化为可执行的 CPM Boost 方案 → 营收提升 **+4.7%**

## 4. 核心贡献

1. **完整闭环**：在真实工业推荐场景中跑通了从调研到生产部署的端到端自动化开发管道，智能体持续驱动全流程。
2. **真实工业奖励**：以在线 A/B 反馈为最终成功标准，直接对齐真实业务价值。
3. **可扩展收益与自我迭代飞轮**：支持多 idea 并发生成与验证，轨迹数据反哺智能体编排框架和基础模型，系统在长期运行中持续增强。

## 5. 总结

AgentX 将推荐系统研发从"人力线性叠加"范式转变为"可复利的智能体杠杆"范式。工程师的角色从亲自执行每一个实验转向定义值得探索的问题和设计更高效的智能体系统。轨迹数据连接了这一转变：底层系统的每一次改进都会被后续所有实验自动继承。
