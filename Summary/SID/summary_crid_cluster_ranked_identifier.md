# CRID: Cluster-Ranked Identifier

**论文标题**: Beyond Semantic IDs: Encoding Business-Value Ranking into Document Identifiers for Generative Retrieval

**作者**: Gui Ling, Zhihong Chen, Yu Li, Tong Xiong, Kunhai Lin, Kaixuan Zhang, Yuliang Yan, Dan Ou, Haihong Tang, Bo Zheng (阿里巴巴淘宝天猫团队)

**arXiv**: https://arxiv.org/abs/2607.11392

---

## 1. 核心问题

生成式检索（GR）将检索建模为序列到序列的生成任务，为每个文档分配一个文档标识符（DocID），然后通过自回归解码进行检索。现有的DocID方案存在两个核心问题：

1. **碰撞问题**：基于离散表示学习的方法（如RQ-KMeans、RQVAE）会导致多个物品被分配相同的DocID，在大规模语料库中尤为严重
2. **目标不匹配**：现有DocID仅基于语义嵌入构建，编码目标是语义重建，而系统优化目标是业务转化。同一语义簇内的物品可能在转化率上相差几个数量级，但却获得相邻甚至相同的DocID

我的理解是模型生成DocID时，先生成语义簇前缀，然后再生成用户在这个context下想要什么样的业务价值商品，从而找到对应（语义簇前缀 + 业务价值排名）的商品。

## 2. CRID设计方案

### 2.1 架构概述

CRID将DocID解耦为**语义聚类**和**业务价值排序**两个部分：

```
DocID = (语义簇前缀 c_s, 业务价值排名 r)
```

其中：
- **语义簇前缀** $\mathbf{c}_s = (c_1, \ldots, c_{L-1})$：捕获粗粒度的查询级语义相似性
- **业务价值排名** $r$：在每个簇内按业务价值统计量（如转化率）进行序数排序

### 2.2 两阶段设计

**阶段一：语义聚类**
- 通过对比学习在查询-物品对上训练物品嵌入
- 使用RQ-KMeans进行量化，得到查询级语义粒度的簇

**阶段二：业务价值排序**
- 在每个语义簇内，按业务价值统计量（如30天转化率）对物品进行排序
- 将排名作为最后一级DocID token

### 2.3 核心优势

1. **无碰撞**：每个簇内的排名映射到唯一物品，构造性地消除碰撞
2. **增量更新**：新增物品通过嵌入距离分配到最近的语义簇，通过日级业务价值统计进行重排序，无需重新训练码本
3. **序数编码**：保持物品间的数值顺序，使自回归模型能够泛化相对物品质量，而非记忆离散类别标签

## 2.4 常见问题讨论

**Q1：DocID的前面几位通过聚类学出来，最后一位直接统计聚类中的业务价值？两者直接拼接？**

**A：是的，完全正确！**

CRID将DocID解耦为语义簇前缀和业务价值排名两部分，直接拼接形成完整的DocID：

$$\text{DocID} = (c_1, c_2, \ldots, c_{L-1}, r)$$

其中：
- 前面L-1位：通过RQ-KMeans对物品嵌入进行量化得到语义簇前缀，生产部署使用 $32768 \times 8192$ 的两级配置
- 最后一位：在每个簇内按业务价值统计量（如30天转化率）排序，排名作为最后一级token

这种设计使得语义簇负责粗粒度召回，排名负责细粒度业务价值区分，同时实现无碰撞和增量更新能力。

**Q2：Serving时如何使用呢？**

**A：通过约束束搜索（Constrained Beam Search）进行自回归解码。**

推理流程分为三个阶段：

| 阶段 | 解码内容 | 约束策略 | Beam Size |
|------|----------|----------|-----------|
| 第一级 | 语义簇选择 (c₁) | 有效路径约束(码本trie) | 100 |
| 第二级 | 语义簇精确定位 (c₂) | 有效路径约束(码本trie) | 400 |
| 第三级 | 业务价值排名预测 (r) | 无trie约束 | 1500 |

**关键细节：**
- **动态Beam Size**：解码越往后，概率分布越分散，需要更大的beam保证召回率
- **约束策略差异**：前两级强制有效路径约束，避免生成无效簇组合；最后一级移除trie约束，因为排名空间统一（所有簇共享8192的排名码本），减少内存开销
- **部署架构**：GR模型作为额外检索通道，与EBR管道并行部署，召回约1300个物品进入精排阶段
- **延迟控制**：满足与现有检索通道相同的延迟要求

**Q3：第三级解码不就是按业务价值排序？**

**A：不是！第三级解码是条件概率预测，融合了统计先验和个性化偏好。**

关键区别在于：

| 阶段 | 内容 | 性质 |
|------|------|------|
| **训练时的标签** | 物品的第三级标签是按业务价值排序得到的排名（如30天转化率排名） | **静态的、统计性的** |
| **推理时的解码** | 模型生成第三级token是基于查询+历史行为的条件概率预测 | **动态的、个性化的** |

模型学习的是条件概率分布：
$$P_\theta(r \mid \mathbf{c}_s, q, \mathbf{h})$$

这个概率融合了两方面信息：
1. **统计先验**：排名靠前的物品在训练数据中出现频率更高，模型会学到这个偏置
2. **个性化偏好**：模型根据当前查询和用户历史行为，可能会调整对排名的预测

**举例说明**：
- 某个簇内，物品A的转化率排名第1，物品B排名第100
- 对于查询"性价比手机"，模型可能预测排名100（因为用户关注性价比，而非单纯销量）
- 对于查询"爆款手机"，模型更可能预测排名1

因此，第三级解码不是简单的业务价值排序，而是统计先验与个性化偏好的结合。

**Q4：训练时，一个商品在一个簇内的价值排名是固定的吗？那如何训练才可以使得推理时候，不同context下，同样的商品能在解码时产生不同的价值呢？**

**A：训练时排名是固定的，但模型通过学习上下文与排名的关联模式，实现了推理时的个性化预测。**

### 为什么固定排名能训练出动态预测能力？

**关键洞察：排名是一个相对位置，模型学习的是"上下文→排名"的映射关系，而非"物品→排名"的固定映射。**

#### 1. 训练数据的上下文多样性

训练数据包含大量不同的查询-物品交互对。同一个物品可能在不同查询下被点击/转化：

```
查询"爆款手机" → 点击排名第1的手机 → 目标排名: 1
查询"性价比手机" → 点击排名第100的手机 → 目标排名: 100  
查询"学生手机" → 点击排名第10的手机 → 目标排名: 10
```

模型学到的不是"手机A=排名1"，而是"在什么查询下应该预测什么排名"。

#### 2. 自回归生成的条件性

模型学习的条件概率是：
$$P_\theta(r \mid \mathbf{c}_s, q, \mathbf{h})$$

条件包含了**查询q**和**用户历史h**，使得模型能够根据不同上下文动态调整预测。

#### 3. 序数编码的泛化能力

CRID使用序数排名而非类别编码，这使得模型能够泛化到相对质量关系：

| 编码方式 | 特点 | 泛化能力 |
|----------|------|----------|
| **类别编码** | 将业务价值分桶（高/中/低） | 差，只能记忆固定类别 |
| **序数编码** | 使用连续排名（1, 2, 3...） | 好，可以学习排名之间的相对关系 |

论文指出："ordinal ranking preserves a numerical order across items, enabling the autoregressive model to generalize over relative item quality rather than memorizing discrete category labels."

#### 4. 训练管道的设计

CRID的训练分为两个阶段：

| 阶段 | 目的 | 输入 |
|------|------|------|
| **DocID记忆** | 预热新增的DocID词汇 | 物品特征 → DocID序列 |
| **SFT（监督微调）** | 学习查询-物品关联 | 查询+历史行为 → DocID序列 |

SFT阶段使用真实用户交互数据，同一个物品在不同查询下会有不同的训练样本。

#### 5. DPO阶段的优化

生产部署还增加了DPO（Direct Preference Optimization）阶段：
- 采样1M查询，每个查询平均10个响应对
- 通过偏好优化进一步提升个性化能力
- 带来约0.5pp的HR@1000提升

### 总结：固定排名 → 动态预测的桥梁

```
训练时（静态标签）          推理时（动态预测）
──────────────────          ──────────────────
物品A在簇内排名=1    ──→   查询"爆款" → 预测排名1
物品C在簇内排名=100  ──→   查询"性价比" → 预测排名100
    ↓                           ↓
模型学习: 查询+历史 → 排名的条件概率
```

模型学习的是**"在什么上下文条件下，应该预测什么排名"**，而不是简单的"物品→排名"固定映射。

### 核心理解

模型生成DocID的过程可以理解为两步决策：

1. **第一步：确定语义范围**——生成语义簇前缀 $\mathbf{c}_s = (c_1, c_2)$，确定用户感兴趣的商品语义类别（如"手机"、"运动鞋"等）

2. **第二步：确定业务价值偏好**——生成排名 $r$，确定用户在当前context下想要什么样的业务价值商品（如"爆款"对应排名靠前，"性价比"对应排名靠后）

最终通过 **（语义簇前缀 + 业务价值排名）** 的组合定位到具体商品：

```
用户查询"爆款手机"
    │
    ├── 第一步：生成前缀 (c₁, c₂) → 定位到"手机"语义簇
    └── 第二步：生成排名 r=1 → 选择该簇内业务价值最高的商品（排名第1）
              │
              ▼
        检索到"热销手机A"
```

```
用户查询"性价比手机"
    │
    ├── 第一步：生成前缀 (c₁, c₂) → 定位到"手机"语义簇
    └── 第二步：生成排名 r=100 → 选择该簇内业务价值中等的商品（排名第100）
              │
              ▼
        检索到"高性价比手机C"
```

这种设计将**语义匹配**和**业务价值偏好**解耦，使得模型能够在同一个语义簇内，根据用户的具体意图（查询+历史行为）灵活选择不同业务价值的商品。

## 3. 分析框架

### 3.1 检索增益分解

CRID的增益来自两个互补机制：

| 机制 | 含义 | 度量方式 |
|------|------|----------|
| **个性化偏好泛化** | 模型利用用户历史中的序列模式 | 通过前缀N-gram匹配分组（3-gram/2-gram/1-gram/0-gram） |
| **统计先验泛化** | 模型从语料库级业务价值统计中泛化 | 通过业务价值排名分组（Rank 0-10/10-100/100-1000/1000+） |

### 3.2 语义簇大小的影响

论文揭示了语义簇大小对检索性能的复杂影响（辛普森悖论）：

- **从排名视角**：较大的簇提高了各组的统计先验，但会稀释顶部排名物品的比例
- **从前缀视角**：较小的簇提高了各组的Hitrate，但会将样本移向较弱的前缀匹配组

生产部署中选择了 $32768 \times 8192$ 的语义码本配置，平衡了两方面的需求。

## 4. 实验结果

### 4.1 离线实验

在淘宝3亿物品语料上的实验结果：

| 方法 | HR@20 | HR@1000 | 无碰撞 |
|------|-------|---------|--------|
| $8192^3$ RQ-KMeans | 16.68% | 63.83% | N |
| w/ OPQ | 20.86% | 67.54% | N |
| w/ SK平衡 | 24.45% | 69.90% | N |
| w/ Tiger | 37.48% | 73.15% | Y |
| w/ FORGE | 37.28% | 72.50% | N |
| **w/ CRID** | **41.20%** | **82.25%** | **Y** |

### 4.2 与EBR基线对比

| 场景 | HR@20 | HR@100 |
|------|-------|--------|
| 搜索内转化 | +13.26% | +10.05% |
| 搜索外转化 | +8.00% | +7.01% |

### 4.3 增量更新能力

| 更新策略 | 覆盖率 | HR@1000 |
|----------|--------|---------|
| 无更新 | 65.08% | 77.52% |
| 仅插入 | 99.15% | 70.44% |
| **全重排序** | **99.37%** | **80.05%** |

### 4.4 线上部署

- 使用Qwen2.5-0.5B作为骨干模型
- 动态beam size：100 → 400 → 1500
- 30天1%流量A/B测试：+0.18% IPV, +0.54% 订单数, **+1.06% GMV**
- 已部署到全量生产流量

## 5. 关键设计亮点

### 5.1 业务价值信号选择

实验表明，CRID对业务价值信号的选择具有鲁棒性：

| 信号 | HR@20 | HR@1000 |
|------|-------|---------|
| 转化排名 | 41.20% | 82.25% |
| 点击排名 | 40.80% | 81.81% |
| 质量分数排名 | 41.15% | 81.82% |

三种信号之间的Spearman相关系数约为0.6-0.7，但Hitrate差异很小。

### 5.2 为什么业务价值排序有效

前缀N-gram分析表明：
- CRID和FORGE在1-gram和2-gram级别表现相当
- CRID在3-gram（完整路径）级别显著超越FORGE（82% vs 72%）
- 这说明在有限模型容量下，统计先验泛化缓解了最后一级解码的瓶颈

---

## 6. 局限性与未来方向

1. **领域限制**：实验仅在淘宝电商搜索场景进行，在推荐等其他领域的有效性有待验证
2. **冷启动偏差**：新上架物品因交互数据有限可能获得次优排名
3. **单一信号**：当前仅使用单个业务价值信号，多信号融合是开放方向
4. **模型规模**：受限于线上延迟，实验使用0.5B模型，更大模型的效果有待探索

---

## 7. 总结

CRID是第一个将业务价值编码为语义簇内序数排名的DocID方案。通过解耦语义聚类和业务价值排序，CRID实现了无碰撞的标识符设计和高效的增量更新能力。分析框架揭示了检索增益来自个性化偏好和统计先验两个互补机制，并阐明了语义簇大小对两者平衡的调控作用。在淘宝3亿物品语料上的实验证明CRID在top-K Hitrate上超越了最强的EBR基线，全量部署带来了+1.06%的GMV提升。
