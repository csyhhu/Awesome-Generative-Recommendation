## 0. 一句话总结 & 理解点评

### 综合理解

> 本文把输入序列组织成：`[用户序列, Recall Target, Recalled Feature]`，其中训练时，Recall Target 是一个正样本的 SID 序列，Recalled Feature 是该正样本的其他传统特征。训练时让模型学习 Recall Target 的分布，以及通过 Recalled Feature 预测 Target 的打分。推理时让模型先生成 Recall Target SID，然后再获取其传统特征进行打分预测。

### 点评

#### ✅ 正确的部分

1. **序列三段式结构**：`[用户序列, Recall Target, Recalled Feature]` 的整体划分正确，对应论文中的 `[P, T_gen, T_rank]`
2. **训练时 Recall Target = ground-truth SID**：正确，是 teacher-forced 输入的正样本 SID 序列
3. **训练时两个学习目标**：学习 SID 分布 + 预测多目标打分，正确
4. **推理时序**：先生成 SID → 再获取特征打分，正确

#### ⚠️ 需要修正的部分

1. **"Recalled Feature" 命名不准确**：这部分不是"被召回的特征"，而是**排序用的物品侧特征**（item profile, content embedding, u-v 交叉统计等）。建议改为 **Ranking Feature / Ranking Segment**，因为它的目的是排序打分，而非召回
2. **"传统特征"低估了特征复杂度**：排序段特征不仅是传统画像/统计特征，还包含内容 embedding 和上游先验等深度特征
3. **排序输入不只是 Ranking Feature**：排序最终输入还拼接了生成段最后位置的隐藏状态 `h^gen_L`（整个 SID 轨迹的语义表征），这是连接召回和排序的关键桥梁，原描述遗漏了这一点

## 1. 背景与动机

现代工业推荐系统通常将**召回（Recall）**和**排序（Ranking）**分离为两个独立阶段：

1. **召回阶段**：从数十亿物品池中检索出数千个候选（生成式召回通过自回归生成语义 ID 实现）
2. **排序阶段**：对候选进行多目标精细打分（如点击、长观看、送礼等）

这种级联架构的核心矛盾：

- **目标不一致**：召回和排序使用不同的优化目标、不同组织的特征，产生于独立参数空间
- **信息损失**：候选生成信息在传递给排序时被压缩为离散候选列表
- **冗余计算**：用户上下文被不同模型重复编码
- **两阶段割裂**：生成的 SID 轨迹与排序特征未在同一序列中进行层间交互

**核心问题**：生成式召回（SID 自回归生成）和多目标排序（判别式特征交互）能否统一为一个 Transformer 序列？

## 2. UniR² 方法总览

UniR² 是一个统一的 **仅解码器 Transformer**，在单个异质序列中组织用户上下文、SID 轨迹和物品特征，实现生成式召回与多目标排序的统一。

### 2.1 统一序列构成

输入序列 \(\mathcal{S} = [\mathcal{P} \| \mathcal{T}_{\text{gen}} \| \mathcal{T}_{\text{rank}}]\) 由三部分组成：

| 段 | 内容 | 说明 |
|---|---|---|
| **用户段 \(\mathcal{P}\)** | 用户画像 + 多行为历史序列（点击、长观看、送礼等） | 作为共享内存，被下游目标 token 读取，扮演编码器 KV Cache 的角色 |
| **生成段 \(\mathcal{T}_{\text{gen}}\)** | `[BOS]`, \(e(q_1)\), \(e(q_2)\), \(e(q_3)\) | 目标物品的 3 层语义 ID（SID），teacher-forced 输入，训练时预测下一层 code |
| **排序段 \(\mathcal{T}_{\text{rank}}\)** | \(e_1(v), e_2(v), \ldots, e_M(v)\) | 物品画像、内容嵌入、交叉统计等补充特征，作为排序查询 |

### 2.2 双查询前缀因果注意力（DQ-PCA）

为解决两个任务对信息可见性的不同需求，设计了**双查询机制**：

- **生成查询 \(Q^{\text{gen}}\)**：携带 SID token，实现**前缀因果注意力**
  - 可访问：完整用户段 + 自身前面位置
  - 不可访问：自身后面位置（标准自回归约束）
  
- **排序查询 \(Q^{\text{rank}}\)**：携带物品特征 token，实现**双向特征融合**
  - 可访问：用户画像 + 生成段 + 排序段（丢弃长历史序列以节省计算）
  - 不可访问：长用户历史序列（已被生成阶段摊销）

**权重共享**：两个分支共享 \(W_q, W_k, W_v, W_o\) 基础投影，但使用独立的 FFN 建立任务级屏障。

### 2.3 生成式召回分支

- 每层使用 DQ-PCA 得到 \(\mathbf{h}^{\text{gen}} \in \mathbb{R}^{L \times d}\)
- 挂载 \(L\) 个独立输出投影 \(W_{\text{gen}}^{(1)}, \ldots, W_{\text{gen}}^{(L)}\)，每层预测对应 codebook 的 code
- 使用加权交叉熵损失：\(\mathcal{L}_{\text{gen}} = \sum_{i=1}^{L} \alpha_i [-\log p(q_i | u, q_{<i})]\)
- 梯度仅通过生成查询的注意力路径回传，不影响物品侧组件

### 2.4 多目标排序分支

- 结合原始用户/作者特征 + SID 最后位置隐藏状态 + 排序隐藏状态
- 输入 MMoE 模型，每个任务塔输出对应目标的预测分数
- 使用 BCE 损失：\(\mathcal{L}_{\text{rank}} = \sum_{t=1}^{T} \omega_t \cdot \text{BCE}(\hat{y}_t, y_t)\)

**梯度隔离**：为防止排序梯度干扰生成主干，采用 LoRA 平衡策略：

- 对排序分支的 Q/K/V 投影注入 **LoRA**：\(\Delta W^{\text{rank}}_X = B^{\text{rank}}_X A^{\text{rank}}_X\)
- 基础投影 \(W_q, W_k, W_v\) 与生成分支共享，但排序侧输出被 detach
- LoRA 仅在排序视图注意力中生效，生成查询仍使用原始基础投影
- 参数分为三组：\(\Theta_{\text{gen}}\)（生成主干）、\(\Theta_{\text{rank}}\)（LoRA + 排序塔）、\(\Theta_{\text{emb}}\)（共享嵌入）

## 3. 训练与部署

### 3.1 训练策略

**数据采样**：
- 排序分支：全量样本流 + 目标自适应 mask，每个判别目标使用独立样本 mask
- 生成分支：下采样，保留所有点击样本 + 随机曝光样本作为正样本

**两阶段训练**：
1. **第一阶段**：仅启用生成损失 \(\mathcal{L}_{\text{gen}}\)，获得稳定分布拟合的主干
2. **第二阶段**：从第一阶段 checkpoint warm-start，加入排序损失进行联合训练

### 3.2 推理管线

1. 用户请求到达 → 提取用户特征 → 自回归生成 SID
2. **KV Cache 复用**：用户前缀和 SID 轨迹的 KV 状态缓存在 GPU
3. CPU 端提取候选物品特征 → 投影为排序 token → 追加到缓存序列
4. **并行化策略**：候选集同时分两路
   - 策略分支：传输给过滤服务，得到过滤标志
   - 排序分支：批量 GPU 前向计算多目标分数
5. 排序完成后仅等待过滤标志，隐藏排序延迟

关键发现：
- 去掉 DQ-PCA 和梯度截断后，模型严重偏向排序（召回掉 44%），验证了优化隔离的必要性

- 去掉 LoRA 后排序性能显著下降（GTR AUC 掉 31%），说明 LoRA 对稀疏目标至关重要

### 4.3 注意力分析

- **召回侧**：SID query 广泛关注行为前缀，与层次化生成过程一致
- **排序侧 LoRA 对比**：无 LoRA 时注意力分散在作者特征上；有 LoRA 后注意力集中在用户画像和生成轨迹上

### 4.4 扩展性实验

深度和宽度缩放实验表明：UniR² 的召回和排序能力均随主干缩放而提升，且未出现明显的任务不平衡。最终选择 3 层、隐藏维度 640 用于线上服务。

## 5. 核心贡献总结

1. **单一序列统一视角**：将用户上下文、SID 轨迹、物品特征组织在一个解码器序列中，使召回轨迹成为排序层间特征交互的**表示桥梁**
2. **DQ-PCA + LoRA 架构**：
   - 双查询机制为因果生成和排序特征融合提供任务特定可见性
   - LoRA 平衡前向表示共享与优化隔离
   - 在每层建立任务级屏障，防止排序梯度破坏生成主干
3. **显著实验效果**：离线实验在召回和排序上均优于强基线，线上 A/B 测试在快手平台取得一致正向收益

## 6. 问答讨论

### Q1：以一个例子，从训练和推理两个角度讲述本文方法的流程

#### 训练流程

假设用户 u 点击了物品 v，物品 v 的 SID 为 `[q1=1234, q2=5678, q3=9012]`，物品 v 的其他特征包括：作者 ID、内容 embedding、u-v 交叉统计等。

**输入序列**：`[用户段 P | 生成段 T_gen | 排序段 T_rank]`

| 段 | 输入内容 | 说明 |
|---|---|---|
| 用户段 P | 用户画像 token + 点击历史序列 + 长观看历史 + 送礼历史等 | 所有用户侧信息，作为共享 KV Cache |
| 生成段 T_gen | `[BOS, e(1234), e(5678), e(9012)]` | 目标物品 v 的 **ground-truth SID**，teacher-forced 输入 |
| 排序段 T_rank | `[e_profile(v), e_content(v), e_cross(u,v), ...]` | 物品 v 的画像、内容、交叉特征等 M 个 token |

**两个查询分支在每一层并行计算**：

- **生成查询 Q_gen**：携带 SID token，做前缀因果注意力
  - 注意力范围：全部用户段 P + 当前位置之前的生成段 token
  - 每层输出：`h_i^gen ∈ R^(4×d)`（4 = BOS + 3 层 SID）
  - 位置 0（BOS）→ 预测 q1，位置 1 → 预测 q2，位置 2 → 预测 q3

- **排序查询 Q_rank**：携带物品特征 token，做双向注意力
  - 注意力范围：用户画像 + 全部生成段 + 全部排序段（丢弃长历史）
  - 同时通过 LoRA 获取排序侧自适应能力
  - 最终输出：`h^rank ∈ R^(M×d)`

**训练目标**：

| 损失 | 来源 | 计算方式 |
|---|---|---|
| L_gen | 生成段输出 | 对每层 codebook 做加权交叉熵：`Σ α_i · [-log p(q_i | u, q_{<i})]` |
| L_rank | 排序段输出 + 拼接 h^gen_L | MMoE 多头 BCE：`Σ ω_t · BCE(ŷ_t, y_t)` |

**两阶段训练**：
- 第一阶段：仅启用 L_gen，训练出稳定的生成主干
- 第二阶段：warm-start 后联合训练 L_gen + L_rank

#### 推理流程

**阶段一：召回（生成）**

| 步骤 | 输入 | 输出 |
|---|---|---|
| 1 | 用户画像 + 行为序列 | 用户段 token |
| 2 | 用户段 KV Cache（预计算并缓存） | — |
| 3 | 自回归生成 SID | 多条 SID 轨迹（beam search 产生 top-K 候选） |
| 4 | — | 缓存：用户前缀 KV + 每个候选的 SID 轨迹 KV |

示例：对用户 u，beam search 生成 5 条 SID 轨迹，对应 5 个候选物品 `{v1, v2, v3, v4, v5}`。

**阶段二：排序（与策略过滤并行）**

| 步骤 | 输入 | 输出 |
|---|---|---|
| 1 | 候选物品 vi 的原始特征 | 投影为排序段 token `T_rank_i` |
| 2 | 缓存的用户 KV + 缓存的 SID 轨迹 KV + 新排序段 token | 单次前向计算 |
| 3 | — | 多目标分数 `(CTR_i, LVTR_i, GTR_i)` |
| 4 | 同时：策略分支对候选做合规过滤 | 过滤标志 |
| 5 | 合并排序分数 + 过滤标志 | 最终排序结果 |

### Q2：生成段产生要被召回的 SID，排序段对这些 SID 进行打分——理解是否正确？

**方向正确，但有两个关键细节需要补充**：

1. **训练时并非"生成→排序"的串行流程**：训练时生成段和排序段在**同一次前向传播中并行处理**同一个 (u, v) 对。生成段处理 ground-truth SID（teacher-forced），排序段处理该物品的特征。排序段的输入中**不仅包含 SID 表示**，还包含物品画像、内容 embedding、交叉特征等。

2. **排序段打分的对象不是"SID"，而是"物品"**：排序段利用 SID 轨迹的**表征**（最后位置的隐藏状态 `h^gen_L`）作为目标语义补充，配合其他物品特征一起对物品的多个目标（点击、长观看、送礼等）进行打分。SID 轨迹在这里是一个**表示桥梁**，而非直接打分对象。

---

### Q3：生成时的 ground-truth 如何获取？生成顺序有影响吗？

**Ground-truth 获取方式**：

使用 **Res-Kmeans**（残差 K-means 量化）为每个物品预分配层级化语义 ID（SID），共 3 层、每层 codebook 大小 8129。例如物品 v 被量化为 `[q1=1234, q2=5678, q3=9012]`。训练时对每个 (u, v) 交互对，取该物品的 ground-truth SID 作为生成段的 teacher-forced 输入。

**生成顺序的影响**：

- **自回归约束**：位置 i 必须基于前面已生成的 code `q_{<i}` 预测当前层 `q_i`，顺序不能调换
- **层级语义**：3 层 SID 从粗到细——q1 对应高层语义属性，q2 中层，q3 最细粒度
- **损失加权**：`α_1 ≥ α_2 ≥ α_3 > 0`，前面的 code 权重更高，因为更早层级决定了物品更高维度的属性

---

### Q4：排序阶段如何获取对应特征？训练 vs 推理的时序关系

**训练时**：生成段和排序段**在同一次前向传播中并行处理**

- 输入序列 `[用户段 | 生成段(ground-truth SID) | 排序段(ground-truth 物品特征)]` 是完整的
- 排序段的特征（画像、内容、交叉统计等）直接从 ground-truth 物品 v 获取
- 同时排序段拼接了生成段最后位置的隐藏状态 `h^gen_L`——编码了整个 SID 轨迹信息
- 两个分支共享同一次 forward pass，排序表示来自已融合生成轨迹的状态

**推理时**：确实是**先生成、再排序**的串行流程

1. 第一阶段：beam search 自回归生成 SID，得到候选物品列表
2. 对每个候选物品 vi：CPU 端提取其原始特征，投影为排序 token
3. 将排序 token 追加到 GPU 缓存的 KV 状态（用户前缀 + 该候选的 SID 轨迹）
4. 执行一次前向计算得到多目标分数
5. 所有候选排序可以**批量并行**完成，且与策略过滤服务并行

关键区别：训练时排序不需要"先等生成"——ground-truth SID 已知；推理时必须先生成候选，才能知道为哪些物品提特征和排序。

### Q6：训练样本粒度——每个样本是单个商品还是多个商品？同一用户多个正样本如何处理？

**每个训练样本是一个 (u, v) 交互对**，即一个用户 + 一个物品。对于用户 u 的多个正样本，会产生**多条独立训练样本**。

示例：

```
用户 u 的行为序列：
  点击历史：[item_A, item_B, item_C]
  长观看历史：[item_E, item_B]
  送礼历史：[item_F]

训练样本构成：
  样本1：[用户u(全序列) | SID(item_A) | 特征(item_A)] → {点击=1, 长观看=0, 送礼=0}
  样本2：[用户u(全序列) | SID(item_B) | 特征(item_B)] → {点击=1, 长观看=1, 送礼=0}
  样本3：[用户u(全序列) | SID(item_C) | 特征(item_C)] → {点击=1, 长观看=0, 送礼=0}
  ...
  样本N：[用户u(全序列) | SID(item_F) | 特征(item_F)] → {点击=0, 长观看=0, 送礼=1}
```

每个样本的**用户段 P 相同**，但生成段和排序段根据目标物品 v 而不同。

**同一用户多正样本的拟合问题**：同一用户上下文需要为多个不同 SID 产生高拟合概率，这正是生成式召回的核心学习目标——学习条件分布 `p(SID | user_context)`。模型需要对用户 u 的所有兴趣物品的 SID 都分配较高概率。这在自回归生成框架下自然成立，与传统推荐中用户向量同时靠近多个物品向量的本质一致。

**采样策略补充**：
- 排序分支：全量样本流 + 目标自适应 mask，每个判别目标独立采样确保足够正负对比
- 生成分支：下采样——保留所有点击样本作为正样本，随机抽样曝光样本，保持对在线曝光分布的拟合
