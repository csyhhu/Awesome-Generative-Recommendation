# Enhancing Taobao Display Advertising with Multimodal Representations: Challenges, Approaches and Insights

- **机构**: 阿里巴巴集团
- **会议**: CIKM 2024
- **arXiv**: 2407.19467

## 背景与动机

淘宝展示广告系统等大规模工业推荐系统长期以来主要依赖稀疏 ID 特征，ID 特征的固有缺陷是无法捕捉多模态数据（图像、文本）中蕴含的语义信息。已有工作尝试将多模态数据接入 ID-based 模型，通常采用两阶段框架：1）通用或场景相关的预训练获得多模态表征；2）将表征接入推荐模型。但很多工业系统仍然只用 ID 特征，原因是担心多模态带来的收益无法覆盖部署成本（预训练编码器、为新item增量生成表征、在线/近线系统改造等）。

论文提出，要成功落地多模态表征需要同时解决三个实际挑战：
1. **预训练任务设计**：如何让多模态表征学到 ID 特征难以捕捉的语义信息；
2. **多模态表征的接入方式**：ID 特征与多模态表征在训练收敛速度等方面存在本质差异，需要专门的融合方法；
3. **生产系统设计**：需要高效地为新 item 实时生成表征并让下游即时可用。

针对以上三点，论文分别提出 **SCL（Semantic-aware Contrastive Learning）预训练方法**、**SimTier 和 MAKE 两种表征接入方法**，以及对应的**在线生产系统架构**。

## 阶段一：多模态表征预训练（SCL）

核心思想：用户的"搜索 query → 后续购买"行为天然蕴含了强语义相似性，可以作为对比学习的正样本对：

| 模态 | 语义相似样本对 |
|---|---|
| 图像 | <用户图片搜索 query 图, 最终购买 item 的图> |
| 文本 | <用户文本搜索 query, 最终购买 item 的标题> |

- **编码器结构**：标准 MoCo 式双塔（Siamese）结构——一个梯度更新的 query encoder $f_q$ 和一个由 $f_q$ 通过动量(EMA)缓慢更新的 key encoder $f_k$，二者结构相同。以图像为例：query 图过 $f_q$ 得到 $q$，购买图(positive)过 $f_k$ 得到 $k_+$，memory bank 中缓存的历史负样本也是此前时刻 $f_k$ 编码并存下的 $k_i$。这是对比学习（SimCLR/MoCo/CLIP 图像塔）的标准做法。
- **负样本**：将同 batch 内其余样本作为负样本，并借鉴 MoCo 思路，用动量更新模型 + 大容量 memory bank（K=196,800）扩充负样本规模，以增大对比学习难度。
- **损失函数**：InfoNCE loss（表征做 L2 归一化后点积计算相似度，温度系数 τ 可学习），拉近 $(q,k_+)$、推远 $(q,\{k_i\})$。
- **模态之间无交互**：准确说是**两套完全平行、互不知道对方存在的 MoCo 双塔**——图像领域一套 $(f_q^{img}, f_k^{img})$，只做「query图 vs 购买图」的图像-图像对比学习；文本领域另一套独立的 $(f_q^{txt}, f_k^{txt})$，只做「query文本 vs 购买标题」的文本-文本对比学习。两套双塔无权重共享、无跨模态对比损失，全文没有类似 CLIP 的图文对齐，不存在跨模态共享语义空间。这与 SimTier/MAKE 的下游用法一致——两者始终只计算「目标item 与历史序列**同模态**表征的相似度」（图跟图比、文本跟文本比），从未出现跨模态相似度计算，因此预训练阶段没有必要做图文对齐。代价是：这套表征不支持"以图搜文/以文搜图"等真正的跨模态检索。
- 在此基础上还引入 **Triplet Loss** 处理人工挖掘的 hard negative（如几乎相同但存在细微差异的商品图片，例如三个几乎一样的枕头），以增强模型区分细粒度差异的能力。
- 实验证明：SCL 显著优于通用预训练的 CLIP-O 和电商域微调的 CLIP-E（Acc@1 从 0.26/0.30 提升到 0.747），且 MoCo 与 Triplet Loss 均有正贡献。

**本阶段产出**：训练好的多模态编码器，以及用它为每个 item 推理得到的**定长稠密向量表征**（训练时冻结、下游按 item id 查表取用）。**关键点是这里没有"统一的 item 多模态表征"**：图像和文本是两套完全独立的 MoCo 双塔分别训出各自的 encoder，因此一个 item 实际拥有的是**互不关联的一组模态向量**（如 $v_i^{image}$、$v_i^{text}$，维度、空间都不必对齐），论文没有把它们融合/投影到统一空间。正文的 CTR case study 也只使用了图像这一路模态；"可泛化到文本/视频"指的是同一套方法（SCL 预训练 + SimTier/MAKE 接入）可以对每个模态分别重复一遍，而非把多个模态合并成一份表征。

## 阶段二：多模态表征与 ID 模型的融合

**架构关系说明**：SimTier 和 MAKE 都是在原有 ID-based 模型（Preliminaries 中描述的、包含 ID embedding + 基于 ID 的历史行为建模模块）之外**新增的并行分支**，而不是替换。原有 ID 通路（历史序列的 ID embedding → 基于 ID 的 DIN 等行为建模模块）保持不变、继续贡献特征；SimTier/MAKE 各自内部单独处理同一条历史序列，但**只用阶段一产出的纯多模态向量**（不掺 ID embedding）计算目标 item 与历史序列的相似度/交互，产出全新的衍生特征。两条分支的输出最终一起拼接进主 MLP——即同一个历史 item，会同时以"ID 身份"和"语义相似度"两种表达分别进入模型，二者互补而非互相替代。

### 两个关键观察

1. **观察1：简化多模态表征的使用方式能提升效果。** 直接将多模态向量与 ID embedding 拼接后接 MLP 的直观做法，效果提升有限，原因是与多模态表征相连的 MLP 参数在与 ID embedding 联合训练时得不到充分学习。相反，把多模态表征转化为语义 ID 等"简化形式"往往效果更好。
2. **观察2：ID 模型与多模态模型的训练收敛 epoch 数不一致。** 工业界 ID 模型通常只训练一个 epoch（防止过拟合，即"one-epoch 现象"），而纯多模态特征模型的性能会随训练轮数增加持续提升。如果多模态相关参数只跟着 ID 模型训练一个 epoch，则会训练不充分。

### 方法一：SimTier

将高维多模态向量转化为低维、更易学习的统计特征：
1. 计算目标 item 的多模态向量 $v_c$ 与用户历史行为序列中每个 item 表征 $v_i$ 的点积相似度 $s_i = v_i \cdot v_c$；
2. 将相似度值域 $[-1,1]$ 划分为 N 个预定义档位（tier），统计每个档位内落入的相似度个数，得到一个 N 维向量（对整条历史序列聚合后的单一向量，而非保留逐 item 的矩阵）；
3. 该 N 维向量与其它 embedding 拼接后送入后续 MLP。这里的"其它 embedding"不局限于 item 侧，而是 Preliminaries 中描述的**整套 ID-based 特征体系**：目标 item ID embedding、用户画像/上下文 ID embedding，以及 ID 序列自身的历史行为建模模块（如基于 ID 的 DIN attention pooling）输出——SimTier 向量是在这些原有输入之外新增的一路特征。

本质是把高维、难学习的多模态向量压缩为统计直方图特征，降低模型学习难度，与观察1呼应。

### 方法二：MAKE（MultimodAl Knowledge Extractor）

针对观察2的训练轮数失配问题，将多模态相关参数的优化与 ID 特征解耦，分两步：

1. **多轮预训练提取知识**：构建一个基于 DIN 结构的行为建模模块，输入 $v_i$（历史序列每个 item）与 $v_c$（目标 item）——两者均直接来自**阶段一预训练好、推理时冻结**的多模态 embedding（按 item id 查表取出），输出 $v_\text{MAKE} = \text{DIN}(\{v_i\}, v_c)$；将其送入 4 层 MLP$_\text{MAKE}$ 输出 logit，以 CTR 预测任务的交叉熵损失做**多 epoch** 预训练，使多模态相关参数得到充分收敛（该预训练任务本身不限定必须是 CTR，具备通用性）。
2. **知识利用**：将预训练收敛后的 $v_\text{MAKE}$ 及 MLP$_\text{MAKE}$ 的中间层输出，与其它 embedding 一并拼接送入下游推荐模型的后续网络层。

实验表明，随着 MAKE 预训练 epoch 数增加，下游推荐模型效果持续提升，验证了"多轮预训练可弥合 ID 与多模态表征收敛速度差异"的假设。

**本阶段产出**：两种方法的输入相同——都是「阶段一产出的 (目标 item 多模态向量, 历史序列多模态向量)」加上用户行为序列结构——但各自产出一个**感知了(目标 item, 历史序列)交互关系的新衍生特征**，这是与阶段一"每个 item 独立一份、无上下文"的静态表征的本质区别：
- SimTier: 产出一个 **N 维统计直方图向量**（对整条序列聚合后的单一向量），无可学习参数、确定性变换、零训练成本；
- MAKE: 产出一个 **target-aware 的 dense 向量 $v_\text{MAKE}$**（及 MLP$_\text{MAKE}$ 中间层输出），由一个独立预训练收敛的 DIN attention 模块产生，相当于把"多模态知识"蒸馏进一个已收敛的小模块。
- 这两个新产出的特征，会与原有的 user／sequence／item ID embedding **拼接在一起，送入下游共享的主 MLP** 做最终 CTR 预测——而不是替换原有特征。若一个 item 同时有图像、文本等多路模态向量（阶段一中彼此独立训练、未融合），SimTier/MAKE 需要**对每个模态分别重复计算一遍**，得到多路模态各自的衍生特征后再一并拼接；论文正文报告的实验**只用了图像**这一路模态，未展示多模态同时接入的组合效果。
- 支撑这两个方法设计的还有两条可复用的方法论洞察：简化优于直接拼接；ID 与多模态存在收敛 epoch 差异。
- 最终验证：两者组合（SimTier+MAKE）接入效果最好。

## 生产系统设计

系统需要保证新广告/新 item 上线后，其多模态表征能被近线训练与在线推理实时使用。整体流程：
- 新 item 创建事件被监听后，自动触发预训练好的多模态编码器对其进行实时推理；
- 推理得到的表征写入一个独立的 **多模态索引表（Multimodal Index Table，即 MIC）**，避免各个模型/场景重复存储表征；
- 下游近线训练系统与在线预测服务直接从该索引表拉取表征。

整个链路将"新 item 创建"到"表征可用于线上预测"之间的延迟压缩到**几秒级别**，从而有效缓解冷启动问题。

**本阶段产出**：不产出算法本身，而是产出让前两阶段成果**可在线上持续生效**的基础设施——一个中心化的**多模态索引表（MIC）**，以及围绕新 item 创建事件的实时触发/推理/写入流水线。它把"离线训练好的 encoder + SimTier/MAKE 模块"转化为线上可随时查询、跨模型/跨场景共享的在线特征服务，是前两阶段成果能够规模化、低成本落地到生产环境的关键保障。

## 实验结果

- **预训练效果**：SCL 相比 CLIP-O/CLIP-E 大幅提升 Acc@1/Acc@5（0.7474/0.8850 vs 0.26/0.36、0.30/0.39）；去掉 Triplet Loss 或 MoCo 均会掉点，说明负样本构造方式很关键。
- **预训练指标与下游效果强相关**：Acc@1 的提升与 CTR 模型 GAUC 的提升高度一致，因此论文用 Acc@N 作为快速评估预训练表征质量的代理指标。
- **CTR 预测整体效果**（相对 ID-based 生产基线的提升）：
  - Vector（直接拼接）：GAUC +0.29%，AUC +0.18%
  - SimScore（相似度得分作为辅助特征）：GAUC +0.77%，AUC +0.40%
  - SimTier：GAUC +0.96%，AUC +0.59%
  - MAKE：GAUC +0.93%，AUC +0.51%
  - **SimTier + MAKE（组合，效果最佳）：GAUC +1.25%，AUC +0.75%**
- **长尾 item 上的提升更明显**：按训练数据中出现频次将 item 分为 8 组，低频（长尾）item 组的相对提升幅度显著大于高频组，说明多模态信息能弥补 ID 特征在长尾 item 上训练不充分的短板。
- **线上 A/B 效果**（自 2023 年中上线以来，已应用于粗排、精排、重排各阶段）：
  - 整体：CTR +3.5%，RPM +1.5%，ROI +2.9%
  - 24 小时内新建广告（冷启动场景）：CTR +6.9%，RPM +3.7%，ROI +7.7%，验证了多模态数据对缓解冷启动问题的显著价值。

## 结论

论文系统性地分享了在超大规模工业广告系统中落地多模态表征的三个核心挑战（预训练任务设计、接入方式、系统实现）及对应解法：SCL 预训练 + SimTier/MAKE 接入 + 实时多模态索引表部署系统。该方案已在淘宝展示广告系统稳定运行并带来显著业务收益，为工业界落地多模态推荐提供了可复用的实践经验。
