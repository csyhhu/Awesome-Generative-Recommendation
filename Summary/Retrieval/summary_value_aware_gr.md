## 核心问题

生成式检索（Generative Retrieval, GR）在电商搜索中展现出强大潜力——通过训练单一自回归模型直接生成目标商品的语义 ID（SID），实现端到端优化。但现有 GR 系统存在两个关键缺陷：

1. **SID 构建缺乏价值感知**：现有方法仅优化语义相似度，不考虑商品的商业价值（如点击率、转化率、GMV），导致高价值商品在检索阶段被遗漏或降权。
2. **候选排序缺乏价值感知**：标准 GR 仅按 SID token 的生成概率排序，反映的是语义相关性而非商业价值，且无法在生成时引入商品侧信息（如价值信号）。

这在工业级电商搜索（如淘宝）中尤为关键，因为业务目标（CTR、CVR、GMV）是系统设计的核心驱动力。

---

## 解决方案：TSGR 框架

TSGR 将价值感知融入商品表示和候选排序两个层面，包含两大核心创新：

### 1. QP-SID（Query-aware Parallel SID）

**目标**：将价值排序编码进 SID 构建中，让高价值、高查询相关性的商品获得更好的 token 索引。

**设计**：
- **语义码本构建**（前两层）：基于品类（Category）和聚类（Cluster）先验，构建 `32768 × 8192` 的语义码本。利用品类嵌入初始化 Level-1，通过 RQ-KMeans 对聚类残差进行量化学习 Level-2。
- **效率码本构建**（第三层）：在每个聚类内部，按商品点击量排序，高价值商品占据更靠前的 token 索引。
- **查询感知并行排序**：为每个聚类构建 4 种并行排序——1 种默认排序（全局点击量）+ 3 种查询条件排序（基于查询词-商品点击统计）。每个查询词匹配聚类中 top-3 最具代表性的词项，过滤掉覆盖率超过 80% 的词项。

**效果**：使生成概率与业务价值和查询相关性对齐。

### 2. VRM（Value-aware Ranking Module）

**目标**：在生成模型内部实现价值感知排序，使单一模型同时充当检索器和预排序器。

**设计**：
- **商品表示**：融合三部分信息——商品侧特征向量（行为统计、品类特征、卖家统计、查询-商品共现）、商品嵌入向量、SID 嵌入向量。
- **用户表示**：复用生成骨干网络的隐藏状态，通过平均池化 + MLP 获得全局用户表示，零额外编码成本。
- **用户-商品交互**：通过交叉注意力机制，让商品表示查询用户上下文表示，捕捉细粒度相关性。
- **多任务评分**：三个并行预测头分别预测 PV、CTR、CVR，推理时用 `PV × CTR` 复合评分重排候选。

**优势**：与生成目标联合优化，消除了传统级联架构中检索与预排序的目标不一致问题，且不增加额外服务延迟。

### 3. 渐进式训练流水线

- **Pre-SFT 多任务预训练**：设计 5 类任务（编码、个性化、检索、协同、推荐），逐步激活模型能力，降低 SFT 阶段的学习难度和数据需求。
- **SFT 加权多正样本训练**：同一会话内的多种交互商品（支付 > 点击 > 浏览）打包为单训练样本，使用加权交叉熵损失，权重满足 `w_pay > w_clk > w_pv`。
- **强化学习探索**：基于 GRPO 的完整 RL 流水线，使用线上排序模型作为奖励源，但增益有限（+0.52% HR@1000），因此未在实际部署中采用。

## 工程价值与启示

1. **统一架构**：TSGR 将检索和预排序统一到单一模型中，消除了传统级联架构的目标错位问题，简化了部署流程。
2. **价值感知的重要性**：在生成式检索中显式编码业务价值信号（通过 QP-SID 和 VRM），而非仅依赖语义相似度，是实现工业级业务目标的关键。
3. **渐进式训练**：Pre-SFT → SFT 的渐进式训练策略有效激活了模型的多维能力，降低了训练难度。
4. **RL 的有限增益**：尽管 RL 提供了直接优化业务目标的能力，但在该场景下增益有限，说明通过架构设计（VRM）引入商品侧信息是更有效的路径。
5. **大规模工业部署**：论文展示了从算法创新到全量部署的完整路径，对其他大规模推荐/搜索系统具有参考价值。

## 深度问答（Q&A）

### Q1：用一个例子，从训练、推理说明整个过程

#### 示例场景
用户在淘宝搜索 **"磁吸手机壳"**，模型需要从海量商品中检索出有价值的候选。

#### 训练阶段

**Step 1: Pre-SFT 多任务预训练**
模型通过 5 类任务激活基础能力：
- **编码任务**：输入"iPhone 15 Pro 磁吸手机壳"→ 输出 SID `[3456, 128, 567]`（学习商品语义到 SID 的映射）
- **检索任务**：输入查询"磁吸手机壳"→ 输出相关商品的 SID（建立查询-商品相关性）
- **个性化任务**：输入用户画像 + 行为序列 → 输出商品标题（激活意图理解）
- 协同过滤任务、推荐任务

**Step 2: SFT 阶段（QP-SID 标签构建）**
训练样本：用户会话中搜索"磁吸手机壳"，点击了商品 A（带磁环的 iPhone 手机壳），浏览了商品 B（普通手机壳）

- 确定商品 A 的前两层 SID：`[3456, 128]`（由品类"手机配件"和聚类"手机壳"决定）
- 确定第三层 token：
  1. 提取查询关键词："磁吸"、"手机壳"
  2. 在聚类 128 中查找代表词项，发现"磁吸"是该聚类的代表词项之一，覆盖率 45%（< 80%，有效）
  3. 商品 A 在"磁吸"条件排序中的排名 = 第 7 位
  4. 商品 A 的第三层 token = `7`（而非默认排序中的 token 值）
  5. 最终 SID：`[3456, 128, 7]`

- 会话内多正样本加权：`w_pay=3 > w_clk=2 > w_pv=1`，商品 A（点击）标签权重为 2
- 生成损失 = `2 × CE(logits, [3456, 128, 7])`
- VRM 同步训练：预测商品 A 的 PV/CTR/CVR，与真实标签做 BCE 损失

#### 推理阶段

**Step 1: 构建输入**
用户查询"磁吸手机壳" + 用户画像（女性、25-30岁、购买力中等）+ 历史行为序列 → 组装成 Prompt

**Step 2: 分层 Beam Search**
- **Level 1**：在前缀树约束下解码（32768 个候选），beam size=400，输出 `[3456]`
- **Level 2**：在前缀树约束下解码（每个 Level-1 有 8192 候选），beam size=400，输出 `[3456, 128]`（聚类"手机壳"）
- **Level 3**：标准 Beam Search（8192 个候选），beam size=10000，输出完整 SID 列表

**Step 3: VRM 价值评分**
对每个候选 SID `(c₁, c₂, c₃)`：
- 从离线特征表获取商品侧特征向量和商品嵌入
- 计算 SID 嵌入 → 拼接得到商品表示 v
- 用户表示 u = MeanPool(BackboneHiddenStates)
- 交叉注意力：a = CrossAttn(v, H_u, H_u)
- 预测 PV、CTR、CVR → 复合评分 = PV × CTR

**Step 4: 重排输出**
按 PV × CTR 降序排列，取 Top-1500 商品直接送入排序阶段（跳过传统预排序）

### Q2："为每个聚类构建 4 种并行排序"具体通过什么方法实现？第三层 token 的数值？

#### 具体实现方法

每个聚类构建 4 种独立的商品排序，本质上是**在同一个 Level-3 码本空间（8192 个 token）中，用 4 种不同的排列方式给商品分配 token 索引**：

#### 排序 1：默认排序 π₀
```
π₀ = argsort(点击量)
```
- 数据：商品过去 30 天的全局点击数
- 不区分查询，按总体热度排序
- 每个聚类中点击量最高的商品 → token `0`，第二 → token `1`，...，最低 → token `8191`

#### 排序 2-4：查询条件排序 πₜ₁, πₜ₂, πₜ₃
每个聚类选出 **top-3 最具代表性的词项**：
```
代表词项筛选：
  1. 统计聚类内所有商品在每个搜索词项下的点击数据
  2. 计算覆盖率：cov(t, C) = （在词项 t 下被点击的商品数）/ 聚类商品总数
  3. 过滤掉覆盖率 > 80% 的词项（区分度太低）
  4. 取剩余词项中最具代表性的 top-3
```
对每个保留的代表词项 t：
```
πₜ = argsort(商品在词项 t 下的点击数)
```
- 数据：商品过去 30 天在特定搜索词项下的点击数
- 按特定查询意图排序

#### 第三层 token 的数值
**第三层 token 的值 = 商品在该排序中的位置索引（0 ~ 8191）**

以"手机壳聚类"为例，假设有 5000 个商品：

| 排序类型 | 商品示例 | token 值 | 含义 |
|---------|---------|---------|------|
| 默认 π₀ | 商品 X（全局点击第 3 高） | 3 | 全局热门度排名 |
| 查询词"磁吸" πₜ₁ | 商品 X（在"磁吸"下点击第 1 高） | 0 | 在"磁吸"查询意图下排名第一 |
| 查询词"液态硅胶" πₜ₂ | 商品 X（在"液态硅胶"下点击第 45 高） | 45 | 在该意图下的排名 |
| 查询词"透明" πₜ₃ | 商品 X（在"透明"下点击第 200 高） | 200 | 在该意图下的排名 |

**关键点**：同一个商品在不同排序下拥有不同的第三层 token 值。模型生成时，根据查询匹配到的词项选择对应的排序路径，使高查询相关性的商品获得更小的 token 索引，从而在 Beam Search 中被更频繁地访问。

### Q3：VRM 是会根据 QP-SID 的生成结果，关联商品侧特征向量，对所有生成结果预测 PV、CTR、CVR？

**是的，理解完全正确。** 具体流程如下：

#### Step 1: 接收 Beam Search 候选
Beam Search 输出 top-N 候选 SID 列表（N 最大为 10000，实际服务取 top-1500）：
```
S = {(c₁⁽¹⁾, c₂⁽¹⁾, c₃⁽¹⁾), (c₁⁽²⁾, c₂⁽²⁾, c₃⁽²⁾), ..., (c₁⁽ᴺ⁾, c₂⁽ᴺ⁾, c₃⁽ᴺ⁾)}
```

#### Step 2: 为每个候选构建商品表示
对每个候选 `(c₁, c₂, c₃)`：
```
商品表示 v_k = [x_k ; e_k ; z_k]
```
- `x_k`：从离线特征表获取的商品侧特征向量
  - 多时间窗口行为统计（浏览数、支付数等）
  - 品类层级特征
  - 全局卖家统计
  - 查询-商品共现特征
- `e_k`：从离线特征表获取的商品嵌入向量（弥补 SID 压缩损失的信息）
- `z_k`：SID 嵌入 = MLP(Emb(c₁), Emb(c₂), Emb(c₃))

#### Step 3: 获取用户表示
```
用户表示 u = MLP(MeanPool(BackboneHiddenStates))
```
复用生成模型的隐藏状态，零额外编码成本

#### Step 4: 用户-商品交互
```
交互表示 a_k = CrossAttn(v_k, H_u, H_u)
```
商品表示作为 Query，用户上下文表示作为 Key/Value

#### Step 5: 预测评分
```
PV 预测:   ŷ_pv = sigmoid(MLP_pv([a_k ; u ; v_k]))
CTR 预测:  ŷ_ctr = sigmoid(MLP_ctr([a_k ; u ; v_k]))
CVR 预测:  ŷ_cvr = sigmoid(MLP_cvr([a_k ; u ; v_k]))
```

#### Step 6: 重排
```
最终排序分数 = ŷ_pv × ŷ_ctr
```

#### 训练时的联合优化
VRM 与生成目标联合训练，总损失：
```
L = L_gen + λ × L_rank
```
- `L_gen`：SID 生成的加权交叉熵损失
- `L_rank`：PV、CTR、CVR 三个任务的 BCE 损失之和
- `λ = 1`：实验中设为 1，两个目标等权

### Q4：查询感知并行排序的度量标准是什么？为什么更小的第三层 SID 数值有助于生成概率与业务价值对齐？

#### 排序度量标准

两种度量标准，均基于 30 天点击统计：

**默认排序 π₀**
```
π₀ = argsort(商品 30 天全局点击数)
```
- 不区分查询意图，按商品在所有搜索场景下的总点击量排序
- 度量的是商品的**全局商业热度**

**查询条件排序 πₜ**
```
πₜ = argsort(商品在特定词项 t 下的 30 天点击数)
```
- 针对特定查询意图，按商品在特定搜索词项下的点击量排序
- 度量的是商品在**特定查询场景下的商业价值**

**查询感知的动态调整**
关键创新在于第三层 token 根据查询动态选择排序路径：
- 商品 X（磁吸手机壳）在默认排序中 token=150
- 但在"磁吸"查询条件排序中 token=0
- 用户搜索"磁吸手机壳"时，选择"磁吸"条件排序，商品 X 的 token 变为 0
- 模型生成 token=0 概率更高，商品 X 更可能出现在检索结果中

### Q5：Pre-SFT 使用的 Base 模型是什么？5 类任务具体怎么进行？

#### Base 模型

使用 **Qwen2.5-0.5B** 作为生成骨干（backbone model）。

#### 5 类 Pre-SFT 任务详解

所有任务混合联合训练，使用标准交叉熵损失，激活模型不同能力维度：

**任务 1：编码任务（Encoding）**
- **目标**：学习商品语义到 SID 空间的映射
- **Prompt**：`商品的标题为：{title}，请预测它的语义id`
- **输出**：SID（如 `[3456, 128, 7]`）

**任务 2：个性化任务（Personalization）**
- **目标**：在文本层面激活用户意图理解
- **Prompt**：`你是一个电商搜索引擎，你的任务是根据用户的个人信息、当前的搜索词、用户历史交互的商品序列，为用户检索下一个商品。用户的性别为：{sex}，年龄为：{age}，购买力级别为：{level}。用户历史交互的商品序列为：{sids}。你检索的商品标题是`
- **输出**：商品标题（自然语言，而非 SID，用于在文本层面激活意图理解）

**任务 3：检索任务（Retrieval）**
- **目标**：建立查询-商品相关性
- **Prompt**：`你是一个电商搜索引擎，你的任务是根据当前的搜索词，为用户检索商品。搜索词为：{query}。你检索的商品是`
- **输出**：SID
- **贡献最大**：与最终目标最接近 (+5.76% HR@1000)

**任务 4：协同任务（Collaboration）**
- **目标**：注入共购协同信号
- **Prompt**：`某商品的标题为：{trigger_title}，它的语义id为：{trigger_sid}，购买过它的用户通常还购买过相似商品，标题为：{target_title}，请预测这一相似商品的语义id`
- **输出**：SID
- **作用**：让 SID 空间编码协同过滤信息，学到"买了 A 的人也买 B"的模式

**任务 5：推荐任务（Recommendation）**
- **目标**：启用个性化和跨域泛化
- **Prompt**：`你是一个电商推荐引擎，你的任务是根据用户的个人信息、用户历史交互的商品序列，为用户推荐下一个商品。用户的性别为：{sex}，年龄为：{age}，购买力级别为：{level}。用户历史交互的商品序列为：{sids}。你推荐的商品是`
- **输出**：SID
- **与检索的区别**：没有查询词，只根据用户画像和行为序列推荐，学习用户长期兴趣

#### 训练策略
- 所有 5 类任务**混合联合训练**，使用标准交叉熵损失
- 不同任务的样本打乱后一起训练
- 每类任务激活不同能力维度，互补组合

### Q6：SFT 加权多正样本训练中，是否需要先生成曝光商品，再通过 VRM 计算点击、支付概率？

#### 整体回答

**训练时模型通过教师强制生成 SID，VRM 使用真实交互标签作为监督信号（而非生成概率）。**

#### 详细流程

**Step 1: 构建训练样本**
从单个用户搜索会话中提取多个交互商品：
```
会话：用户搜索"磁吸手机壳"
  - 商品 A：购买 (pay) → w_pay = 3
  - 商品 B：点击 (click) → w_clk = 2
  - 商品 C：浏览 (pv) → w_pv = 1
  - 商品 D：未曝光 (unpv) → 不作为正样本
```

**Step 2: 生成损失 L_gen（教师强制）**
```
对每个正样本 k ∈ {A, B, C}：
  loss_k = w_k × CE(model_logits, ground_truth_SID_k)
```
- 模型尝试生成商品 A、B、C 的 SID token
- 每个商品有独立注意力掩码，防止交叉干扰
- 权重 w_pay=3 > w_clk=2 > w_pv=1，更关注高价值商品

**Step 3: VRM 排名损失 L_rank（关键区别）**
VRM 使用**真实交互标签**作为监督信号：
```
对每个正样本 k ∈ {A, B, C}：
  VRM 输入：
    - 商品表示 v_k = [商品侧特征 ; 商品嵌入 ; SID嵌入]
    - 用户表示 u = MeanPool(BackboneHiddenStates)
    - 交叉注意力 a_k = CrossAttn(v_k, H_u, H_u)
  
  VRM 预测：
    ŷ_pv  = sigmoid(MLP_pv([a_k ; u ; v_k]))
    ŷ_ctr = sigmoid(MLP_ctr([a_k ; u ; v_k]))
    ŷ_cvr = sigmoid(MLP_cvr([a_k ; u ; v_k]))
  
  真实标签（ground truth）：
    y_pv  = 1 （商品被浏览过）
    y_ctr = 1 （商品被点击过）
    y_cvr = 0 （商品未被购买）
  
  BCE 损失：
    loss_rank_k = BCE(ŷ_pv, 1) + BCE(ŷ_ctr, 1) + BCE(ŷ_cvr, 0)
```

**Step 4: 联合优化**
```
总损失 = L_gen + λ × L_rank  （λ = 1）
```
两个损失同时反向传播，L_gen 优化 SID 生成，L_rank 优化价值预测。

#### 训练 vs 推理的区别

| 阶段 | SID 来源 | VRM 输入 | VRM 输出 |
|------|---------|---------|---------|
| **训练** | 教师强制（已知正确答案） | 真实商品侧特征 + 真实 SID 嵌入 | 与真实标签做 BCE |
| **推理** | Beam Search（模型自由生成） | 真实商品侧特征 + 生成的 SID 嵌入 | PV × CTR 作为排序分 |

#### 总结

- **训练时**：VRM 学会从 SID + 商品侧特征预测 PV/CTR/CVR（用真实标签监督）
- **推理时**：VRM 对 Beam Search 生成的每个候选计算价值分数，用 `PV × CTR` 重排
- **VRM 本质**：一个价值评估器，学习"什么样的商品在当前查询下更有价值"，与生成过程解耦

## 与 UniR²（arXiv:2607.24439）的对比分析

> UniR²：在单个解码器序列中统一生成式召回与多目标排序

### 核心问题：是否都是「生成 SID → 关联特征 → 打分」？

**高层思路相似，但实现架构存在本质差异。**

### 相同点

| 维度 | TSGR (2607.18796) | UniR² (2607.24439) |
|------|-------------------|---------------------|
| **任务定义** | 生成式召回 + 价值感知排序 | 生成式召回 + 多目标排序 |
| **SID 生成** | Beam Search 生成 SID | Beam Search 生成 SID |
| **排序输入** | SID 嵌入 + 商品侧特征 | SID 隐藏状态 + 商品侧特征 |
| **排序输出** | PV × CTR 复合评分 | 多目标分数（CTR/LVTR/GTR） |
| **推理流程** | 先生成 SID → 再对候选打分 | 先生成 SID → 再对候选打分 |
| **训练损失** | L_gen + λ·L_rank | L_gen + L_rank |

### 关键差异

#### 1. 架构集成方式

| 维度 | TSGR | UniR² |
|------|------|-------|
| **排序模块** | **外挂式**：VRM 是骨干网络之上的独立模块，使用 Cross-Attention | **嵌入式**：排序是同一序列的一个段（segment），共享 Transformer 骨干 |
| **注意力机制** | Cross-Attention：商品表示 Query → 用户上下文 Key/Value | DQ-PCA：双查询前缀因果注意力，生成分支和排序分支有不同的信息可见性 |
| **参数共享** | 共享骨干 Embedding + 隐藏状态 | 共享 Q/K/V 基础投影 + 独立 FFN + LoRA |
| **梯度隔离** | 无特殊机制，直接联合优化 | LoRA + 梯度截断，防止排序梯度破坏生成主干 |

#### 2. 排序模块的具体设计

**TSGR - VRM：**
```
商品表示 v_k = [x_k ; e_k ; z_k]
  - x_k: 商品侧特征向量
  - e_k: 商品嵌入
  - z_k: SID 嵌入（通过 MLP 压缩）

用户表示 u = MeanPool(BackboneHiddenStates)

交互: a_k = CrossAttn(v_k, H_u, H_u)

评分: [a_k ; u ; v_k] → 3 个 MLP → PV/CTR/CVR
```

**UniR² - 排序段：**
```
输入序列: [用户段 P | 生成段 T_gen | 排序段 T_rank]

排序查询 Q_rank:
  - 携带物品特征 token
  - 注意力范围: 用户画像 + 全部生成段 + 全部排序段（丢弃长历史）
  - 通过 LoRA 获取排序侧自适应能力

排序输入:
  - 排序段隐藏状态 h_rank
  - 生成段最后位置 h^gen_L（SID 轨迹表示）
  - 原始用户/作者特征

评分: 拼接后 → MMoE → 多目标分数
```

#### 3. 核心创新的不同

| 维度 | TSGR | UniR² |
|------|------|-------|
| **核心创新** | QP-SID（查询感知并行 SID） | DQ-PCA + LoRA 统一架构 |
| **SID 设计** | 4 种并行排序，第三层 token 根据查询动态选择 | 标准 Res-Kmeans 量化，无价值感知 |
| **价值感知** | 编码在 SID 中（token 索引 = 价值排名） | 仅通过排序分支引入，SID 本身无价值信息 |

### 两种范式的本质区别

| | TSGR | UniR² |
|---|------|-------|
| **范式** | **生成后打分**（Post-Generation Scoring） | **序列内统一**（In-Sequence Unification） |
| **类比** | 先写完作文，再用评分标准打分 | 写作和评分在同一过程中完成，评分标准作为写作的一部分 |
| **优势** | 模块化，易于扩展排序特征 | 更紧凑的架构，无额外模块开销 |
| **劣势** | 存在生成-排序的表示鸿沟 | 需要复杂的注意力机制平衡两个任务 |
| **价值感知** | SID 构建时就编码价值 | 依赖排序分支引入价值信息 |

### 补充思考

1. **TSGR 的价值感知更前置**：通过 QP-SID 在 SID 构建时就编码了价值信息，生成过程本身就倾向于产生高价值商品的 SID。而 UniR² 的 SID 是标准量化，无价值偏好。

2. **UniR² 的架构更紧凑**：排序分支作为序列的一部分，可以直接利用生成过程中的中间表示，而 TSGR 的 VRM 需要额外的 Cross-Attention 模块。

3. **工程实现的 trade-off**：
   - TSGR：VRM 可以独立迭代和扩展（如新增排序特征），但需要处理生成-排序的表示对齐问题
   - UniR²：序列内统一更优雅，但需要精心设计注意力机制和梯度隔离

4. **两篇论文代表了生成式召回与排序统一的两种主流路径**，各有适用场景。
